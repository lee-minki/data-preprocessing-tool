System Narrative

같은 기준으로 전처리 결과를 만드는 시스템

왜 전처리 표준화가 필요한지, 왜 모델링용 산출물을 같은 규칙으로 묶어야 하는지 핵심만 정리했습니다.

  • 같은 파일도 사람마다 필터 기준과 이상값 처리 강도가 달라지기 쉽습니다.
  • 그 차이는 결과 파일 품질과 검증구간 구성까지 흔듭니다.
  • 이 시스템은 원본 확인 → 기준 설정 → 자동 저장의 공통 흐름으로 그 편차를 줄입니다.
시스템 바로가기 실무 매뉴얼 보기 업무 흐름 보기
기억해야 할 한 줄

핵심은 기능 추가보다 누가 작업해도 같은 방향의 전처리 결과를 만들게 하는 운영 장치라는 점입니다.

1. 흩어진 전처리 기준

모델링 데이터 준비는 반복되지만 기준은 문서, 경험, 개인 판단에 흩어져 있는 경우가 많습니다. 그래서 같은 원본도 제거 강도와 검증구간 준비 방식이 달라집니다.

사람마다 다른 정리 방식

필터 조건, 이상값 처리 강도, 시간 보정 여부가 개인 경험에 따라 달라질 수 있습니다.

설명하기 어려운 결과 파일

왜 이 파일이 이렇게 만들어졌는지 사후 설명이 길어지고, 검토자 입장에서 재현도 어렵습니다.

검증과 점검까지 연결되지 않음

전처리와 Validation 분리, Simulation 생성이 끊겨 있으면 프리비전 연계 준비 시간이 늘어납니다.

2. 흐름을 고정하는 표준화

같은 순서로 판단하게 만듭니다

이 시스템은 먼저 원본 추세를 보고, 다음에 기준을 정하고, 마지막에 결과를 검토하도록 흐름을 고정합니다. 순서가 고정되면 설정 실수와 해석 편차도 함께 줄어듭니다.

산출물의 의미를 통일합니다

전처리데이터, 정상 Validation 20%, Simulation Data를 같은 규칙 아래 묶어두면 파일명보다 파일의 역할이 일관되게 유지됩니다.

3. 네 단계 작업 흐름

도구의 목적은 복잡한 메뉴를 늘리는 것이 아니라, 실제 준비 업무를 짧고 반복 가능한 네 단계로 압축하는 데 있습니다.

01

파일 업로드

XLSX / XLS 파일을 불러오고 기본 구조를 확인합니다.

02

원본 추세 확인

우측 차트와 표에서 튀는 구간과 시간 흐름을 먼저 읽습니다.

03

기준 설정

이상값 처리, 필터, 시간 보정, Validation / Simulation 조건을 정합니다.

04

실행과 검토

자동 저장된 결과와 로그, 비교 차트로 설정이 적절했는지 다시 확인합니다.

4. 재현성과 설명 가능성

반복 작업을 빠르게 만드는 것도 이점이지만, 더 중요한 효과는 누가 해도 같은 흐름으로 같은 성격의 파일을 만든다는 점입니다. 그래야 결과를 검토하고 설명하고 개선하기 쉬워집니다.

Operational Effect
반복 시간 단축

업로드부터 저장까지 별도 수작업 단계를 줄여 실제 준비 시간을 압축합니다.

Quality Effect
기준 일관화

같은 화면에서 같은 순서로 판단하기 때문에 설정 편차를 줄일 수 있습니다.

Governance Effect
설명 가능성 확보

검토자와 관리자도 어떤 기준으로 파일이 만들어졌는지 흐름 기준으로 이해할 수 있습니다.

Prevision Effect
연계 준비 단순화

Validation 분리와 Simulation 생성이 한 흐름에 묶여 프리비전 업로드 준비가 수월해집니다.

Procedure Manual v1.7.0

Prevision 조기경보용 데이터 전처리 프로그램 절차형 매뉴얼

이 프로그램은 조기경보 시스템(Prevision)용 시계열 데이터를 한 번에 준비하기 위한 올인원 도구입니다. 원본 파일 로드, 필터링, 이상값 제거, 정규화, 시간 재정렬, Validation 데이터 생성, 시뮬레이션용 파일 저장까지 한 흐름으로 처리할 수 있습니다. 이 문서는 “왜 쓰는지 → 어떤 순서로 쓰는지 → 버튼을 무엇으로 설정해야 하는지 → 어떤 파일이 저장되는지” 순서대로 설명합니다.

목차

1. 프로그램 목적왜 이 프로그램을 쓰는지 2. 전체 절차처음부터 끝까지 작업 순서 3. 파일 열기원본 데이터 로드와 미리보기 4. 필터 설정학습 대상 구간 정리 5. 이상값 처리정상 학습 데이터 품질 맞추기 6. 정규화/시간 처리모델 입력 형태 정리 7. 전처리 실행/Validation/저장메인 페이지 작업 순서 8. Validation 생성검증/시뮬레이션용 파일 만들기 9. 파일명 규칙저장 결과와 접미어 의미 10. 체크리스트실행 전/후 점검과 트러블슈팅

프로그램 목적과 사용 이유

1

무엇을 위한 프로그램인가

Prevision 조기경보 모델이 읽을 수 있는 형태로 시계열 데이터를 정리하는 프로그램입니다. 센서 원본 데이터에서 학습에 불필요한 구간을 제거하고, 모델 테스트용 validation/시뮬레이션 데이터를 따로 만들 수 있습니다.

왜 필요한가

조기경보 모델은 시간축이 맞고, 이상값이 정리되고, 필요한 태그만 남은 데이터를 써야 합니다. 원본 파일을 그대로 넣으면 학습 성능이 흔들리거나, validation 구간 구성이 어려워집니다.

무엇을 얻는가

전처리본, validation이 붙은 파일, validation만 분리한 파일을 얻습니다. 즉 학습용 데이터와 검증/시뮬레이션용 데이터를 같은 규칙으로 정리할 수 있습니다.

핵심 기능

Excel/CSV 로드, 다중 필터, 이상값 제거, Min-Max/Z-Score, 시간 정규화, 시간 재정렬, Validation 생성, 프리셋 저장.

운영 관점 장점

한 화면에서 작업 순서를 유지할 수 있고, 대용량 데이터도 진행률과 로그를 보면서 처리할 수 있습니다.

결과 활용

전처리본은 학습용 기준 데이터, validation 파일은 후단 솔루션에서 검증 구간 드래그 또는 시뮬레이션 데이터로 활용합니다.

이 앱은 “실제 train/test를 내부에서 잘라 학습시키는 모델 툴”이 아니라, 학습과 validation 준비를 위한 데이터 정리 툴입니다. 즉 학습에 넣을 데이터 품질을 맞추고, validation용 synthetic 구간을 생성해 후단 솔루션에서 쉽게 구분하도록 돕는 역할입니다.

1

이상값 처리 기준을 고릅니다. 현재 정책상 이상값이 포함된 행은 전체 삭제됩니다. 제거된 행은 validation 생성 재료로 활용됩니다.

5
전처리를 실행합니다. 필터링 → 이상값 제거 → 정규화 → 시간 보정/재정렬 순서로 처리됩니다.

7
전처리본을 저장합니다. 기본 저장명은 입력 파일명 뒤에 _processed_시각이 붙는 방식입니다.
8
Prevision에서 학습/검증에 활용합니다. 전처리본은 학습 기준 데이터로, validation 파일은 검증 구간 또는 시뮬레이션 데이터로 사용합니다.

필터의 목적

모델이 학습할 구간을 먼저 좁히는 단계입니다. 점검 중 구간, 정지 구간, 센서가 물리적으로 말이 안 되는 구간을 미리 빼면 학습 기준이 더 안정됩니다.

어떻게 읽으면 되나

  • AMBIENT_TEMP >= 15: 주변 온도가 15 이상인 구간만 사용
  • FAN_CURRENT range 30~60: 팬 전류가 정상 운전 범위 안인 구간만 사용
  • 여러 줄은 모두 AND 조건으로 적용

왜 먼저 필터를 거나

이상값 처리 전에 불필요 구간을 줄여야 통계 기준이 더 깔끔해집니다. 즉 필터는 “학습 후보군을 정리하는 단계”, 이상값 처리는 “남은 후보군을 깨끗하게 만드는 단계”로 이해하면 됩니다.

현재 정책

이상값이 하나라도 포함된 행은 해당 행 전체를 제거합니다. 셀 하나만 비우는 방식이 아니라, 학습에 들어갈 한 시점 전체를 통째로 정리하는 방식입니다.

방법 선택 기준

  • 2σ: 엄격한 기준. 정상 범위를 좁게 봅니다.
  • 2.5σ: 기본 추천값. 너무 빡빡하지 않고 실무에서 쓰기 무난합니다.
  • 3σ: 느슨한 기준. 극단값만 제거하고 싶을 때.
  • IQR: 분포가 찌그러졌거나 비대칭일 때 유리합니다.

왜 중요한가

학습용 데이터에 비정상 스파이크가 많이 섞이면 정상 패턴 학습이 흐려집니다. 반대로 너무 강하게 지우면 정상 변화까지 빠질 수 있으니, 보통은 2.5σ부터 시작해 결과를 비교합니다.

제거된 행은 단순히 버려지지 않습니다. 이후 Validation 생성 시 “제거행 기반 이상 구간”을 만들 때 재료로 다시 사용됩니다.

정규화는 왜 쓰나

태그마다 값의 단위와 크기가 다르면 후단 모델이나 시각화가 한쪽 값에 끌릴 수 있습니다. 이런 경우 값 범위를 맞춰주는 것이 정규화입니다.

  • Min-Max: 0~1 범위로 맞춤. 현재 기본 선택값입니다.
  • Z-Score: 평균 0, 표준편차 1 기준으로 맞춤.

시간 정규화는 언제 쓰나

데이터 시각이 2분 간격이어야 하는데 00:01:59, 00:04:02처럼 조금씩 밀려 있을 때 씁니다. 가장 가까운 간격으로 스냅해서 시간축을 바로잡습니다.

시간 재정렬은 언제 쓰나

필터 후 남은 데이터에 새 시작 시간을 주고, 일정 간격의 연속 시계열처럼 다시 배열하고 싶을 때 사용합니다. 후단 솔루션에서 시계열 구간을 드래그할 때 더 다루기 쉬워집니다.

화면에서 설정한 값이 순서대로 적용됩니다. 일반적인 실행 흐름은 필터링 → 이상값 제거 → 정규화 → 시간 정규화 → 시간 재정렬입니다.

왜 Validation 버튼이 메인 화면에 있나

이 프로그램의 주 작업 흐름은 전처리 직후 validation/시뮬레이션 파일을 이어서 만드는 것입니다. 그래서 Validation 생성은 분석 기능이 아니라 메인 작업 버튼으로 두는 편이 실제 사용 순서와 맞습니다.

결과 저장은 무엇이 저장되나

현재 메모리에 있는 전처리 결과 전체가 저장됩니다. 이 파일은 “정상 학습용 기준 데이터”로 보는 것이 가장 자연스럽습니다.

수동 저장 파일명 규칙

입력 파일이 abc.xlsx이면 기본 제안 파일명은 abc_processed_YYYYMMDD_HHMMSS.xlsx 형태입니다. 즉 입력 파일 뒤에 _processed_시각이 붙어 구분됩니다.

전처리본 저장은 사용자가 경로를 직접 정하는 수동 저장입니다. 반면 Validation 생성은 메인 화면 버튼으로 실행하며, 원본 파일 폴더에 3개 파일을 자동 저장하는 별도 흐름입니다.

이 기능의 목적

조기경보 모델을 학습한 뒤, 선택한 태그에서 이상이 점진적으로 발생하는 상황을 검증하거나 시뮬레이션하기 위한 파일을 만드는 기능입니다. 즉 “정상 학습용 데이터”와 “검증/시뮬레이션용 데이터”를 같은 기준 위에서 관리하게 해줍니다.

이 화면에서 결정하는 것

  • 어떤 태그에 이상을 만들지
  • validation 전체 길이를 몇 %로 만들지
  • 정상/제거행 기반 이상/sigma 기반 이상 비율을 어떻게 나눌지
  • sigma 구간에서 얼마나 강한 이상까지 밀어낼지

Training / Validation 관점에서 읽는 방법

전처리본은 학습용 기준 데이터로 보고, validation 생성 결과는 검증/시뮬레이션용으로 사용합니다. 특히 *_prepro_with_valid.xlsx는 뒤쪽 validation 블록이 붙어 있어 후단 솔루션에서 구간을 나누기 쉽고, *_valid.xlsx는 validation 블록만 별도로 떼어서 시뮬레이션 입력으로 쓰기 좋습니다.

이 기능은 “실제 미래 validation 구간을 원본에서 잘라내는 기능”이 아니라, 전처리 결과를 기준으로 validation용 synthetic 블록을 새로 만드는 기능입니다.

전처리본 + validation 블록이 한 파일에 같이 들어 있다는 뜻입니다.

_valid

validation 블록만 따로 저장한 파일이라는 뜻입니다. 시뮬레이션 전용 파일로 쓰기 쉽습니다.

자동 저장 3종은 원본 파일과 같은 폴더에 생성됩니다. 즉 원본 파일이 있는 위치를 기준으로 같은 이름 뿌리에 접미어만 달라지는 구조입니다.

실행 전/후 체크리스트와 자주 생기는 문제

10

실행 전 체크

1. 문서보안 해제 여부 확인
2. 날짜 컬럼/숫자 컬럼 인식 확인
3. 필터 조건이 너무 강하지 않은지 확인
4. 시간 간격(예: 2분)과 시작 시각 확인

전처리 후 체크

1. 로그에 실패 메시지가 없는지
2. 행 수가 지나치게 줄지 않았는지
3. 전처리본 미리보기 값이 정상적인지
4. 필요하면 트렌드 차트로 주요 태그 확인

Validation 생성 후 체크

1. 대상 태그만 이상 추이가 들어갔는지
2. 파일 3종이 원본 폴더에 생성됐는지
3. validation 비율과 구간 비율이 의도대로인지
4. 후단 솔루션에서 구간 지정이 쉬운지

문제 확인할 것 즉시 조치
파일 로드 실패 문서보안, 파일 형식, 손상 여부 문서보안 해제 후 다시 로드
Validation 생성 불가 전처리 실행 여부, 제거된 행 존재 여부 필터/이상값 처리를 먼저 실행하고 다시 생성
파일이 덮어써짐 같은 이름 파일이 폴더에 이미 있는지 생성 전 기존 파일 백업 또는 폴더 정리
모델 입력값이 이상함 정규화 사용 여부, 시간 재정렬 간격 후단 솔루션 기준에 맞게 Min-Max/시간 간격 재검토
이 매뉴얼은 먼저 내용을 충분히 담는 방향으로 작성했습니다. 다음 단계에서는 실제 사용자 피드백을 받아 중복 설명을 줄이고, 화면 캡처가 가능해지면 HTML 모형을 실제 앱 스크린샷으로 교체하면 됩니다.
